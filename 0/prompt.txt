## Project description so far
Project: A natural-language observability interface for high-frequency robot telemetry, demonstrated on collision diagnosis.

- OpenTSLM is not a classifier, it’s not a forecasting model.
    - Natural language should be a first class citizen in time series data analysis: joint text + time-series reasoning, with generated rationales and answers rather than a fixed classification head.
- Aim: Move beyond fixed dashboards and classifiers. Let an operator **query raw robot telemetry directly in natural language** and get answers grounded in the temporal signal.
    - Every queryable feature increases the richness of the demo.
    - YES/NO label  + action classification + regression (temporal localization) → altogether from natural language.
        - Maybe aggregate information into a queryable database.
- Benchmark dataset: https://zenodo.org/records/21927431
- Benchmark data set: p1 & p2 https://github.com/zhang-zengjie/robot-raw-collision-signals
    - Input:  7 synchronized joint-torque channel, 1 kHz, ~1 s windows
    - underlying events  and event onset time
    - We also have the URDF model, so you can visualize it  https://github.com/jkaniuka/kuka_lwr4plus_urdf?utm_source=chatgpt.com

## Potential things we want from the model 
Queries we allow:
Labels
“Did external contact occur?”	yes/no
“Was this accidental, intentional, or free motion?”	3-way class
"Where is the strongest evidence?" Onset temporal interval 

Pseudolabels

compute a normalized disturbance score metric per channel (because each channel has different statistics)

“Which joint shows the largest disturbance?”	J1–J7
“Which joints are most affected?”	ranked / subset

Eval:
1. Event semantics free / intentional contact / accidental collision
Metric: accuracy/F1.

2. Joint attribution “Which joint has the strongest evidence?”
Metric: exact accuracy.

3. Temporal localization “When does the event happen?” MAE=∣t_hat−t∣
