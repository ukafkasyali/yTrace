Update the KUKA Part I TimeNet connector so that `PosMsr` is represented in **radians** instead of using the current `dimensionless` compatibility placeholder.

This should be treated as a **high-confidence inferred unit**, not as an explicitly documented fact from the supplied Batch 01 archive.

## Evidence

The following evidence supports `PosMsr = rad`:

- Across all five runs, observed `PosMsr` values are roughly within ±1.44.
- Interpreted as radians, this corresponds to approximately ±82.5°, which is realistic for the KUKA LWR4+ trajectories and occupies a plausible fraction of the robot’s joint range.
- Interpreted as degrees, the motion would be only about ±1.44°, which is implausibly small.
- The variable naming is consistent with KUKA FRI conventions:
  - `PosMsr`
  - `MsrTrq`
  - `MsrExtTrq`
  - `CmdTrq`
- KUKA FRI documentation uses radians for commanded joint positions.
- Independent LWR literature using `GetMeasuredJointPositions()` reports joint positions in radians.
- No supplied Batch 01 source file contains evidence of conversion to degrees:
  - no `rad2deg`
  - no `deg2rad`
  - no `180/pi`
  - no `pi/180`
- The original logger implementation is not included, so direct experiment-level proof is unavailable.

Assessment:
```text
PosMsr unit: rad
confidence: high
resolution type: inferred
direct source statement: unavailable
```
