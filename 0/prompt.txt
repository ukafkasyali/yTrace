The CNN is not better on every metric. It is better on event semantics, median onset, and output reliability. OpenTSLM slightly wins contact F1 and onset mean/P90, while joint accuracy is essentially tied.
Why the CNN wins:
- Conv1D directly detects local torque spikes and shapes.
- Each target has a dedicated supervised head and loss.
- It trained on all 29,393 examples.
- It outputs typed values directly—no JSON-generation failures.
- Its checkpoint was selected using the main downstream metric, macro-F1.
I found no obvious CNN training bug. Validation macro-F1 was 0.990 and test was 0.975, with a normal learning curve and sensible early stopping at epoch 23. Its weak point is onset outliers: median 18 ms, but P90 274 ms.
The OpenTSLM comparison has several real concerns:
- The reported checkpoint is explicitly a canary, apparently limited to 8,192 examples and three epochs—not a comparable full-budget run.
- It learns indirectly: signal → soft-prompt tokens → language model → generated JSON. Token loss also covers formatting and evidence prose rather than focusing only on classification.
- Checkpoint selection uses language-model validation loss, not macro-F1 or parse validity.
- 22.1% of outputs failed strict parsing.
- Evaluation uses summary prompts, while the canary training mixed summary and atomic prompts.
- The warm-start path does not explicitly apply the YAML LoRA rank/alpha/dropout settings; it relies on OpenTSLM defaults ([train_opentslm.py (line 56)](/Users/Student/Downloads/EHL_Zurich/ysamet/model_training/src/robot_observability/train_opentslm.py:56)).
- The comparison branch lacks the OpenTSLM manifest, learning curve, raw predictions, and checkpoint. Its quoted metrics also contain fields not produced by the evaluator committed on this branch, so the result is not fully reproducible.
One correction to my earlier warning: the contact F1/accuracy values are not mathematically impossible—the evaluator handles malformed values differently between those metrics. They are still not cleanly comparable.
Conclusion: the CNN run looks valid; OpenTSLM has not yet received a fair, fully traceable training run. I would not conclude that CNN fundamentally beats OpenTSLM until OpenTSLM is retrained at full budget, selected using downstream validation metrics, and evaluated with the same strict typed scorer and record IDs.
